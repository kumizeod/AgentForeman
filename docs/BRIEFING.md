# 开工前：先与 chairman 把需求谈清楚

目标是让研究者在离开前确定任务，而不是在每个执行步骤里等待审批。
本版将澄清与确认接入通用任务的**合作、对抗模式**；原有实验训练、
Council 和代码候选入口保留各自流程。

## 前端操作

1. 打开本地控制台的 **共享委员会 → 合作 / 对抗工作台**。
2. 保持默认勾选的“先与 chairman 澄清需求，确认后再开工”。填写初始想法，
   选择节点、预算、资料和已有检查器。先启动 `pool serve` 和主席 worker；
   主席须有有效登录/API 凭据，并处在其可接任务时间窗口内。
3. 主席询问目标、输入条件、交付物、验收、约束、优先级、不做的事情，以及
   可自主决定、需要暂停和默认处理的边界。你在对话框回答。
4. 主席整理出约定后，你查看完整约定和执行参数。目标可直接编辑，其余字段
   可通过完整约定 JSON 修改，也可继续与主席讨论。保存修改产生新版本；
   未保存的修改会禁用确认按钮。
5. 点击“确认 vN 并正式开工”。现在才创建合作/对抗执行任务。保持协调器和
   各 worker 运行即可离开页面；关闭网页不会停止任务。

主席只能建议和整理，不能代替你确认。它也不能改节点、预算或检查命令。
确认表达的是对目标、权限和验收方式的同意，不是对任务结论正确性的认证。
旧的“直接执行”路径仍可通过取消勾选使用，以兼容需求已明确的任务。

## 任务约定

约定包含：

- `goal`：要解决的问题。
- `inputs`：已提供的输入与条件，不得凭空宣称资源可用。
- `deliverables`：产物 ID 与描述，必须包含 `answer`。最终提案必须提供这些
  产物；合作贡献者仅负责自己的子任务。
- `acceptance`：验收标准。`automated` 必须引用已有检查器 ID；`manual`
  明确表示尚需人工/外部验收，不能被模型一致同意或其他检查通过替代。
- `constraints`、`priorities`、`exclusions`：约束、取舍顺序和范围外事项。
- `autonomy`：可以自主决定、需要暂停澄清、可以采用默认值的情况。

执行配置由人提供，包括模式、成员、主席、独立审查者、轮数和时间预算。
资料和检查器在澄清创建时冻结，Python 检查脚本也会复制快照。
确认绑定的是“约定 + 执行参数 + 资料摘要 + 检查器摘要”的具体版本与指纹。
更换资料或验收检查器请新建澄清任务，不会让主席在后台生成新命令。

## 执行与恢复

- 确认前仅向主席派发澄清任务；其他执行者不能提前领取该执行任务。
- 等待人回复时不继续派发模型任务。每轮澄清有超时，整个澄清有轮数上限。
  主席失败或超时进入等待补充，不能自动启动。
- 执行预算从确认后创建子任务时开始，不消耗在人等待回复的时间里。
- 先保存启动意图和稳定子任务 ID，再创建子任务；崩溃后恢复同一个 ID。
  相同版本的重复确认返回同一个子任务，旧版本/指纹会被拒绝。
- 已确认的约定被复制到执行任务，进入各角色上下文，并在恢复时校验完整性。
  启动后不能原地修改原约定；新目标需要新的澄清与确认。
- 执行者主动报告 `scope_change.required=true` 时暂停该任务并保留原因，
  不接受替换目标。它不会自动重写约定。暂停后可新建澄清任务，明确新版本，
  再启动新的执行；当前版本不做原运行的就地目标迁移。
- 未自动覆盖的人工验收项始终列入待验证问题，最终状态为 `needs_evidence`。

自然语言约束、偏好和暂停条件首先是给各角色的明确指令，并非全部都能由
程序证明满足。范围变化暂停依赖执行者主动报告，不能保证识别所有隐性语义
漂移。程序能强制的部分包括版本/指纹、角色配置、预算、产物 ID、冻结检查和
验收状态。检查器仍是用户事先配置的可信本地代码，不是新增加的沙箱。

## CLI

```text
python -m agentforeman briefing start --project ./my-experiment --idea "分析销售数据，给出可靠的总额和限制" --execution examples/briefing/execution.json --evidence examples/debate/evidence.json --checks examples/debate/checks.json
python -m agentforeman briefing status BRIEFING_ID --project ./my-experiment
python -m agentforeman briefing message BRIEFING_ID --project ./my-experiment --version 1 --text "需要 JSON，并解释输入数据的局限"
python -m agentforeman briefing confirm BRIEFING_ID --project ./my-experiment --version 2 --sha256 REVIEWED_SHA256
```

示例先注册 `author`、`critic`、`chair`，并把 `examples/debate/check_total.py`
复制为项目中的 `check_total.py`。状态输出提供当前版本、指纹、对话和约定。
`edit --contract contract.json` 保存新版本，`stop` 终止尚未提交启动意图的澄清，
`advance` 可手工推进。协调器会自动推进正在等待主席或恢复启动的状态。
文件位于 `.foreman/briefings/ID/`，包括对话、历史版本、摘要、启动绑定和报告。

## 验证范围

测试覆盖确认前不启动、主席不能自行确认、问题未解不就绪、版本编辑与旧确认
拒绝、重复确认、启动前后两处崩溃恢复、检查脚本快照、确认后预算、人工验收
保留、范围变更暂停、API 权限和浏览器全过程。
测试模型回复使用明确标注的脚本；HTTP、原生进程、实际检查器和状态恢复是真实
执行。这不证明真实主席一定能理解所有需求，也不代表真实多账号整夜质量已验证。
