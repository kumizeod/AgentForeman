# Validation disclosure

## v0.4 overnight validation

The current suite contains 67 tests. The initial 62-test implementation `f966437`
passed all nine native OS/Python combinations in
[run 39448938675](https://github.com/kumizeod/AgentForeman/actions/runs/39448938675).
Four further tests cover absolute deadlines at supervisor launch/runtime, context
preparation crossing the deadline, and a reset that passes while receipts are
processed. Ten targeted checks passed after those changes. A passed reset now uses
short bounded backoff instead of unnecessarily sleeping another five hours.

The subsequent 66-test native run exposed a transient Windows 3.12 read denial
while `process.json` was being replaced (job 118723034344 in
[run 39450304520](https://github.com/kumizeod/AgentForeman/actions/runs/39450304520)).
Receipt readers now retry Windows PermissionError for at most one second; permanent
denials remain visible and Unix denials are not retried. A new contract test and
the affected recovery test passed in a 14-test local follow-up. Final native results
are recorded separately when available.

`overnight-test-results.txt` records 62 passing Linux tests (the previous 48 plus
14 overnight/quota tests). After the full run exposed a benign detached-Popen
ResourceWarning, the launcher was updated to reap background children from a daemon
thread. Eight targeted follow-up tests passed, including real detached CLI submission,
automatic timer wake, preserved partial edits and read-only metadata RPC.

`overnight-summary.json` is generated by `python -m tests.record_overnight_evidence`.
It demonstrates planner quota → wait → resume → worker quota → wait → resume →
real training/independent verification → report, retaining one experiment ID and
two quota resumptions. Its reset windows are explicitly accelerated to 0.25 seconds;
it is NOT a real five-hour/account-reset test. Both model roles and rate-limit metadata
are labeled fixtures; the training, checkpoint and verifier are real.

Coverage includes no extra model calls before wake, a morning deadline during quota
waiting, quota retry caps, refusal to recover protected partial edits, controller
death/restart, existing-run reuse, duplicate background submission and actual timer wake.
Live subscription quota exhaustion/reset and compatibility with the user's installed
Codex CLI remain unverified. v0.3 native CI evidence below does not establish v0.4 CI.

Recorded on 2026-10-19 in a Linux/Python 3.12 environment with NumPy available.

## What the recorded run proves

`sample_archive.zip`, `sample_report.json`, `sample_summary.json` and
`sample_report.md` come from a real local run. Its editor was
`tests/fixture_codex.py`, an explicitly identified deterministic **test fixture**.
It does not call a model. The run does perform actual gradient descent on CSV
files, save NPZ weights, recompute validation predictions in a separate verifier
process and create a portable archive.

This example's score change is produced by a predetermined fixture increasing
optimization budget and width. It is engineering evidence, not evidence of an
agent independently discovering a better architecture.

## Automated verification

The v0.2.0 local suite contains 38 tests (including 12 platform contract tests).
All were executed on Linux; Windows/macOS contract mocks are labeled as such.

`test-results.txt` contains the final unittest run. It covers normal execution,
manager SIGKILL while training survives, checkpoint/verifier rejection, restart
receipt reuse, concurrent run/supervisor ownership, CLI failure/retry, missing CLI
installation/retry, timeout, cancellation, protected edits, no-op edits, symlinks,
fake scores, archive corruption and replay after extracting the archive.

`package-check.txt` records building the distributable wheel and loading its
bundled templates from a clean installation target.

Reproduce the local evidence without Codex (test workflow only):

```bash
python -m unittest discover -s tests -v
python -m tests.record_evidence --output ./evidence-new
python -m tests.record_campaign_evidence --output ./evidence-new/campaign-summary.json
```

## Not verified here

- A live, authenticated `codex exec` inference run. This environment has no
  Codex CLI installed and no model account was configured for this project.
- GPU execution, PyTorch integration or 5090 performance.
- Remote/multi-host execution and multi-user isolation.
- Multi-seed scientific improvements or live model-led multi-round experiments.

The real adapter follows the cited official headless interface; validate CLI
version, sandbox behavior and model access on your own Windows/macOS/Linux installation.
No test fixture is selected by a production CLI fallback.
